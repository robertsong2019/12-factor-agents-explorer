### What was produced
- [研究笔记](catalyst-research/exploration-notes/2026-06-13-hybrid-retrieval-fusion-beyond-rrf.md) ✅
- ~250 行可运行 TypeScript (6 种融合算法对比 + 3 assertions 全通过)
- 5 条关键洞察 + 竞品融合策略对比表 (7 个系统)
- 5 个下一步行动 (含代码片段和预期提升数据)

### Key insights
1. **k=60 对 Agent 记忆次优** — 小 k 值 (10-20) 的 top-1/top-10 gap 是 k=60 的 3-5x
2. **CombMNZ 共识奖励天然适合三路异构搜索** — 三路同时检出 = 高置信度
3. **Weaviate 切到 RSF 是产业信号** — 分数可解释性比 rank-only 更有价值
4. **Adaptive fusion 是差异化机会** — 无系统同时做 adaptive + 三路融合
5. **Graph 路排名语义需重定义** — 从 ranked list 改为 weighted bonus 更合理

### Code verified
- Benchmark: 8 种策略在模拟 agent memory (10 nodes × 3 paths) 上对比
- Assertions: RRF 共识排序 ✅, CombMNZ 共识优先 ✅, 小 k gap > 大 k gap ✅
- k=1 gap 0.0833 vs k=60 gap 0.0003 — 278x 差异！

### Cycle 1: confidenceScore (ef48bbd)
- **What**: Multi-factor quality scoring (0-1) for structured output results
- **Factors**: syntax (0.15) + schema (0.35) + semantic (0.25, -warnings) + consensus (0.25*agreement) + recovery (-retries)
- **APIs**: `scoreFromReport()`, `scoreFromConsensus()`, `scoreFromRecovery()`, `compareConfidence()`, `meetsThreshold()`
- **Tests**: 14 (178→192)
- **Insight**: Without consensus, max score = 0.75 ("high"); reaching "very_high" (≥0.9) requires consensus agreement

### Cycle 2: temperatureSchedule (f5159f8)
- **What**: Adaptive retry temperature strategy — adjusts based on failure type
- **Strategy**: syntax failure → +0.3 (more diverse), schema → +0.15 (moderate), semantic → -0.1 (conservative), success → decay to baseline
- **APIs**: `TemperatureSchedule` class, `escalatingSchedule()`, `oscillatingSchedule()`, `TemperatureSchedule.plan()`
- **Tests**: 16 (192→208)
- **Insight**: Semantic failures need *lower* temperature (more precise), not higher

### Cycle 3: validationSummary (63a7c88)

- **Tests**: 13 (208→221)
- **Use case**: Log validation outcomes, dashboard monitoring, debug retry chains
